# Backlog

Features worth having, in the order they will be built. Each lands as one commit with tests,
docs and benchmarks where speed matters. Move an item to Done when it ships.

## Next

1. **Scenes and a type registry.** Register component types once; save and load whole worlds
   without listing types per snapshot.
2. **Swift concurrency bridges.** Events and changes as an `AsyncSequence` (Afluent), and
   `@MainActor` systems run on the main actor by a schedule.
3. **Profiling.** Time per system per run, and the schedule's dependency graph as DOT.
4. **Checked accesses.** A debug-build record of the columns and resources a system with a
   hand-written `access` touches while it runs concurrently, trapping on undeclared reads as
   undeclared writes already trap. Systems declared by their parameters cannot reach anything
   else, so this covers hand-written conformances only; it needs a lookup check that costs
   nothing in release builds.

## Done

- Sparse-set world with copy-on-write, queries with filters, in-place updates, commands,
  resources.
- Schedules ordered by `after` / `before`.
- Tuple query rows: `for (entity, position, velocity) in world.query(...)`.
- Benchmarks with package-benchmark.
- Change detection: added and changed ticks per component, `.added` / `.changed` filters, and
  each system's previous run tracked by its schedule.
- Events: typed, double-buffered `Events<E>` resources, per-reader places, `UpdateEvents`.
- Run conditions: `runIf` on systems and schedules.
- Relationships: a parent and children per entity kept by the world, walks, cascading despawn.
- Entity reservation: `Commands.spawn` returns a handle later commands in the buffer resolve;
  `apply` returns the spawned entities.
- Bundles: the `Bundle` protocol and `BundleBuilder`; components are bundles of themselves.
- Observers, as component hooks: `onAdd`, `onInsert`, `onRemove`, run after the firing
  operation. In-place changes are left to change detection.
- Snapshots: `WorldSnapshot<each C>` is `Codable`; `World(restoring:)` keeps every handle.
- World equality: `==` on snapshots of `Equatable` components, independent of storage order.
- Parallel updates: `parallelUpdate` chunks entities across cores; `@Sendable` bodies keep it
  deterministic.
- Parallel schedules: `Access` declarations, `World.runConcurrently`.
- Groups: EnTT-style owning groups; queries and updates over exactly the grouped types walk
  the packed front with no lookups.
- Queries as values: `Query` of components and `AnyOf` groups, `anyOf` filters, `query(_:)` and
  `update(_:over:)` writing one to three types; fixed-arity shapes generated by Bazel.
- Systems declared by their parameters: `@System` (swift-syntax) builds `access` and `run(in:)`
  from `Query`, `Update<A>.And<B>.Over<…>.Where<…>`, resource and event readers and writers and
  `inout Commands`; filter types `With`, `Without`, `Added`, `Changed`, `AnyOf`; schedules run
  in waves of a dependency graph of conflicts and constraints, `run(on:)` concurrently and
  `runSerially(on:)` one system at a time, applying queued commands after each wave.
- Ambiguity detection: `Schedule.ambiguities()` lists conflicting systems no constraint orders;
  `ambiguous(with:)` marks pairs whose order does not matter.
- Required components: `static var required` on a component, inserted when missing, transitively,
  after the explicit components, from the world and from commands.
- Removal detection: `trackRemovals(of:)`, `removed(_:by:)` per reader over `RemovedComponent`
  events sent by a removal hook, and the `RemovedComponents` system parameter, started by
  `System.initialize(in:)` before a system's first run.
- Named schedules and states: `Simulation` with `ScheduleLabel`s (`startup`, `fixedUpdate`,
  `update`, custom), a fixed timestep with an accumulator and a maximum frame time, `Time` and
  `FixedTime` resources, and `States` with `CurrentState`, `NextState`, `onEnter` / `onExit` /
  `onTransition` schedules and `inState`.
- System sets: `SystemSet` marker types joined with `inSet`; every system type is a set, so
  `after`, `before` and `ambiguous(with:)` name either; a nested schedule takes them for all its
  systems.
- Disabled entities and default filters: `Disabled` and `registerDisablingComponent` hide
  entities from queries and updates unless they read, name or allow the type (`allowing`,
  `Allows`).
- Entity cloning and prefabs: `clone(_:)`, `Prefab` (a disabling component) and
  `spawn(from:)`, in the world and in commands.
- Column spans: `withSpan(of:_:)` and `withMutableSpan(of:_:)` lend a component type's
  storage as `Span` / `MutableSpan`, the mutable one marking every component changed.
- Cached queries: `cache(_:)` keeps the entities meeting a query's structural conditions
  current, and visits whose conditions imply them walk only those.
- Relations: `Relation` types (exclusive, carrying values, cleaning up by removing or despawning
  sources), `relate`/`unrelate`, `targets`/`sources`, `Targets<R>` components, and
  `.related(_:to:)` filters that walk only a target's sources.
- The hierarchy as the `ChildOf` relation: exclusive, despawning its sources, queryable with
  `.related(ChildOf.self, to:)` and `Targets<ChildOf>`.
- Observers: `EntityEvent`s triggered on an entity run its observers and every entity's,
  propagating up the hierarchy; `onAdd` and `onRemove` hooks for entities starting or stopping
  to match a query.
- Indexes by value: `index(_:)` and `lookup(_:)` over a `Hashable` component, kept current
  by structural changes and rebuilt at the next tick after changes in place.
